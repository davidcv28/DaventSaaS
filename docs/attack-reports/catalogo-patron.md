# Attack Report — Catálogo público y render de patrones (DesignPattern)

Fecha: 2026-11-15 · Alcance: `/api/stores/public/<slug>/*`, `pattern/document|products|bridge.js|script.js`, `sanitize_markup`/`pattern_render`/`pattern_document`, `pattern_bridge.js`, `PatternSurface.vue`, catálogo público (filtros/facetas/precios), reviews, contacto, preview tokens. Backend `:8000` (Django + DRF, SQLite dev), front `:5173`. Tiendas QA: `davent`, `vertice`, `mi-qa` (+ `obra-viva` como tienda no publicada). DB de solo lectura: los ataques de escritura se auditaron por revisión de código.

**Resultado general: superficie muy endurecida.** El pipeline `render → escape por variable → fragmentos escapados → sanitize_markup sobre el HTML renderizado → CSP por nonce + iframe sandboxeado (origen opaco)` cierra el XSS almacenado/reflejado en todas las vías probadas. No se encontraron 500s, inyecciones ejecutables ni fugas de PII/keys. Los hallazgos son de consistencia de gating, defensa en profundidad del puente y superficie residual de bajo impacto.

## Ataques resistidos (evidencia negativa)

| Superficie | Ataque | Resultado |
|-----------|--------|-----------|
| `sanitize_markup` | `on*=` con comillas simples/sin comillas/`/`, `<script>` sueltos/auto-cerrados, `javascript:`/`vbscript:`/`data:text/html` ofuscados por entidades en `href/src/action/formaction/xlink:href/poster/background/srcset/ping`, `<base>`, `<object/embed/iframe/frame>`, todo `<meta>` (refresh) | Todos eliminados/neutralizados (`pattern_document.py:27-70,322-335`); corre ADEMÁS del escape de variables, sobre el HTML ya renderizado (`:373`) |
| XSS por campos de tienda | `store_name`, `headline`, `description`, `about_*`, `plans[]`, `faqs`, `team`, `announcements`, categorías, marcas, nombres/descripciones de producto, reviews (`name`, `text`, `owner_reply`), `feature_schema` | Doble barrera: `strip_tags`+`escape` en `_text`/fragmentos (`pattern_render.py:127-132`) y escape por variable en `DesignPattern.render` (`models.py:371-380`); solo `type:list` va raw y todo fragmento raw se construye con `escape()`/`_attr()` |
| `{{placeholder}}` arbitrario | `{{__class__}}`, variable no declarada | Se reemplaza por `''` — fail-closed sobre `pattern.variables` (`models.py:371-375`) |
| URLs dueño en href/src | `video_url`, `videos[]`, `live_stream_url`, `whatsapp`, `instagram`, `facebook`, `tiktok`, `maps` | Normalizadas/validadas a hosts conocidos en serializer (`serializers.py:488-592`, `:645-666`) o servidas vía redirect `/r/<kind>` (dato real nunca en HTML — `pattern_render.py:175-185`); `SCRIPT_URL_RE` cubre lo residual |
| Imágenes | `object_url` con keys manipuladas, SVG con script | Solo `*_key` del servidor (R2) — el contenido subido se normaliza a WebP (`normalize_image`), no hay URL externa libre; alt/attrs escapados; `img-src https: data:` del CSP |
| Slugs | `..%2f`, `%00`, unicode, `DAVENT` mayúsculas, `-weird-`, inexistente, tienda no publicada (`obra-viva`), bloqueada | 404 en todos — regex `[a-z0-9-]+` + `is_published`/`is_blocked` + `has_public_link` (`viewset.py:761-768`) |
| Catálogo — filtros | `category=abc/99999`, `brand` inválidos, `q=%_%` y 8 KB, `min_price=1e999/-5`, `max_price=abc`, `features=notjson`, `sort=price;DROP/name desc`, `page=-1/99999/abc`, `offer/new/event` raros | Todos 200 con parseo defensivo — whitelist de sorts, `_id_list` máx 50 ids, `_price_bound` clamp a numeric(12,2), `q` casefold `[:80]` en haystack Python (sin regex/SQL → sin ReDoS ni inyección), `page` ignorado por diseño (`viewset.py:142-258`) |
| Cross-store | `?product=<id de vertice>` bajo slug `davent` | `data-ds-pdp-missing` — contexto vacío, sin datos del producto ajeno (`viewset.py:736-742`); `is_exclusive` filtrado siempre |
| Reviews | GET cross-store/inexistente → 404; POST sin sesión → 401; identidad por `request.customer`, no por payload | Correcto (`viewset.py:1254-1316`); GET no expone email (name + inicial — `serializers.py:256-263`) |
| Contacto | POST sin captcha → 400; captcha = challenge firmado + nonce single-use + 5 intentos + min-time + fail-closed cache | Correcto (`contact.py:67-110`); honeypot + throttle dedicados |
| Query params reflejados | `?surface="'><script>"`, `?theme=dark"><script>`, `?style=<script>`, `?preview=fake&template=x` | Normalizados a charset seguro o caen a default (`pattern_document.py:377-381`); `preview/template/style` sin token válido se ignoran; `template` viaja urlencoded al `script.js` sin riesgo |
| CSP del documento | escape vía CSS (`</style`), atributos de `<html>`, preload links | `sanitize_css` quita `</style`; `data-ds-*` saneados por regex/whitelist; preload `escape()`+máx 2; `X-Frame-Options: SAMEORIGIN` + `default-src 'none'` + `connect-src 'none'` (sin exfil por fetch propio) |
| Auth zombie | Bearer vencido en endpoints públicos | `get_authenticators` devuelve `[]` en `PUBLIC_ACTIONS` — no hay 401 espurio (`viewset.py:414-426`) |

## Recomendaciones

1. **CP-01**: aplicar `allowed_templates_of(store.user)` en `pattern_for_template`/`render_store_pattern` (y en `StoreCustomizationPublicSerializer.to_representation`) — el gating no puede vivir solo en el PATCH ni en el front.
2. **CP-02**: pasar `_pattern_store(slug)` en `public_pattern_bridge` como hacen `script.js`/`products`.
3. **CP-03**: acotar `int(product_id)` a `<= 2**63-1` antes del lookup.
4. **CP-04**: rechazar `?features=` > ~4 KB antes de `json.loads` (en fingerprint y en el filtro).
5. **CP-06**: endurecer `onMessage`: además de `e.source`, guardar una referencia al documento legítimo (p. ej. token de sesión generado por el host y propagado solo vía CSP-nonce'd bridge) o cerrar el relay `ds-api` tras navegación del frame (`frame.src`/`load` event guard). Considerar `customerHttp` solo si el patrón realmente necesita POST de reviews (hoy la whitelist lo permite a cualquier contenido del frame).
6. **CP-05**: sacar `contact` de `PUBLIC_API_RE` para GET o exigir que el bridge pida captcha por un canal separado del envío.
